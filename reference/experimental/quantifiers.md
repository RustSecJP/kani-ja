# Kani の量化子 {#quantifiers-in-kani}

量化子は形式検証における強力な機能で、ある範囲の値にわたる性質を表現できます。Kani は量化子を実験的にサポートしており、ユーザはプログラムの仕様を簡潔で表現力豊かに書けます。

## サポートされている量化子 {#supported-quantifiers}

Kani は現在、次の量化子をサポートしています。

1. **全称量化子**:
   - 与えられた範囲のすべての値について性質が成り立つことを保証します。
   - 構文: `kani::forall!(|variable in range| condition)`
   - 例:

```rust
#[kani::proof]
fn test_forall() {
    let v : [u8;10] = [10; 10];
    assert!(kani::forall!(|i in (0,10)| v[i] == 10) );
}
```

2. **存在量化子**:
   - 与えられた範囲に、性質が成り立つ値が少なくとも 1 つ存在することを保証します。
   - 構文: `kani::exists!(|variable in range| condition)`
   - 例:

```rust
#[kani::proof]
fn test_exists() {
    let v : [u8;5] = [1, 2, 3, 4, 5];
    assert!(kani::exists!(|i in (0,v.len())| v[i] == 3));
}
```


### 制限事項 {#limitations}

#### 述語の中の安全性チェック {#safety-checks-in-predicates}

`-Z valid-value-checks` または `-Z uninit-checks` を使うと、明示的な安全性チェックを含む述語は現在拒否されます。それらのチェックは純粋な量化子の式の中に保持できないからです。この走査は式の中に埋め込まれた文も対象にします。これらのオプションを有効にすると、関数呼び出しは戻り値が使われていなくても保持され、ヘルパの本体は量化子のインライン化の前にチェックされます。認識するのは `safety_check`、`arithmetic_overflow`、`exact_div`、`finite_check` のプロパティクラスです。すべてのアサーションクラスが保持されることを保証するものではありません。クロージャを構築する前に行われる安全性チェックは有効なままです。

どちらかの追加の UB オプションを使うと、[CBMC #9189](https://github.com/diffblue/cbmc/issues/9189) のため、文式（statement-expression）へのフォールバックを必要とする存在量化の述語も拒否されます。純粋な式に直接変換できる述語には影響しません。量化子のインライン化を必要とする呼び出しは、GOTO の本体がない場合（本体のない組み込み関数を含む）に拒否されます。

この制限は、通常のポインタを使う述語にも影響します。たとえば、どちらかの追加の UB オプションを使うと、次の述語はすべてのアクセスが範囲内であるにもかかわらず拒否されます。

```rust
#[kani::proof]
fn pointer_witness() {
    let values = [1u8, 2];
    let ptr = values.as_ptr();
    assert!(kani::exists!(|i in (0, 2)| unsafe { *ptr.add(i) == 2 }));
}
```

追加の UB オプションを使わない場合でも、ネストしていない述語の抽出は、算術チェックや通常の Rust のアサーションを含むデフォルトのチェックが保持されることを保証しません。追加の UB のガードも、ネストしていない述語の中にある通常の Rust のアサーションはカバーしません。検証が成功しても、述語の中でそれらのチェックが成り立つことは保証されません。直接の抽出は、チェックや関数呼び出しを検出すると、追加の UB オプションがなくても、ネストした述語を保守的に拒否します。これは、この制限を新しくサポートされたキャプチャの射影にまで広げないためです。これには、デフォルトのヌルポインタチェックを伴う生ポインタの参照外しも含まれます。ポインタをキャプチャして比較するだけなら、参照外しは必要ありません。関数ポインタを通した間接呼び出しも、量化子のインライン化ではサポートされていません。

#### 配列のインデックスアクセス {#array-indexing}

量化子の性能は、量化された式の中のコールスタックの深さに影響されることがあります。コールスタックが深すぎると、Kani は量化子を効率よく評価できず、タイムアウトやメモリ不足になる可能性があります。実際、Rust の配列のインデックスアクセスは深いコールスタックになるため、量化子で問題を起こすことがあります。これを緩和するには、量化子を使うときに、配列のインデックスアクセスの代わりに *unsafe* なポインタの参照外しを使うことを検討してください。ポインタの参照外しを使っても、[量化子の述語に対する安全性チェックの制限](#safety-checks-in-predicates)を回避できるわけではありません。ネストしたポインタの読み取りは依然として拒否されることがあります。例:

```rust
#[kani::proof]
fn vec_assert_forall_harness() {
    let v = vec![10 as u8; 128];
    let ptr = v.as_ptr();
    unsafe {
        kani::assert(kani::forall!(|i in (0,128)| *ptr.wrapping_byte_offset(i as isize) == 10), "");
    }
}
```

#### 量化された変数の型 {#types-of-quantified-variables}

現在は、量化された変数はすべて `usize` 型であると仮定しています。つまり、量化子で指定する範囲は `usize` と互換でなければなりません。
 将来はほかの型もサポートする予定ですが、今のところは量化子で `usize` の範囲を使うようにしてください。

#### ソルバのバックエンドのサポート {#solver-backend-support}

デフォルトの SAT ベースのソルバのバックエンドは、上限が定数の量化子しかサポートしません。上限が記号的な（コンパイル時にわからない）量化子はエンコードできず、黙って制約のない値に置き換えられてしまいます。これは不健全です。そのような量化子を含む `kani::assume` は強制されず、そのような量化子を含む `kani::assert` は誤って失敗することがあります。

結果を健全に保つため、バックエンドが量化子を落とした場合、Kani は検証を `FAILED` として報告し、量化子をサポートする SMT ソルバのバックエンドを使うよう案内します。これらの量化子を検証するには、ハーネスに `#[kani::solver(z3)]` を付けてください（またはコマンドラインで `--solver z3` を使ってください）。
